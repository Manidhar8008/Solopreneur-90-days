# Open Source vs Paid

The product architecture has two layers.

| Layer | Solopreneur 90 Days | 90-Day Client Engine |
|---|---|---|
| Access | Public | Paid |
| Core curriculum | Yes | Yes + implementation depth |
| 90-day roadmap | Yes | Personalized |
| Market selection | Framework | Individual review |
| Offer design | Framework | Offer teardown + iteration |
| Acquisition | General playbooks | Personalized pipeline system |
| Sales | General framework | Call/proposal review |
| Delivery | General templates | Delivery architecture + review |
| AI workflows | Public examples | Private implementation workflows |
| Accountability | Self-directed | Structured |
| Feedback | Community/open contribution | Direct review |
| Case studies | Public | Private teardowns + participant evidence |
| Guarantee | None | ₹1,00,000 first-client target with published eligibility/refund terms |

## Product principle

**Free teaches the system. Paid compresses the path from system → execution → evidence.**

The paid offer should never depend on hiding the fundamental method. Its defensibility comes from:

- personalization;
- feedback loops;
- execution support;
- implementation assets;
- private examples;
- accountability;
- speed;
- accumulated customer evidence.

## The funnel

```text
GitHub / Open Source
        ↓
Learner runs the 90-day system
        ↓
Learner discovers execution gaps
        ↓
Paid program becomes the implementation layer
        ↓
Participant builds pipeline
        ↓
₹1,00,000 first-client target
        ↓
Case study / repeatable system
        ↓
Company
```

## Messaging rule

Do not market the open-source project as a disguised sales funnel. Make the public repository genuinely useful.

Do not market the paid program as “secret information.” Market it as **structured implementation with accountability and a clearly defined outcome/guarantee policy**.
